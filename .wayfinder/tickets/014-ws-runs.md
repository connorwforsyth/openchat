## Question

The in-process `RunExecutor`, the Postgres `StreamChannel` (chunk table + LISTEN/NOTIFY),
the runs and stream routes, the one-run-per-branch queue, tool approvals, the resumable
`useChat` transport, in-process pg-boss with a job registry, and title generation
(`PLAN.md` D4, §8 Chat run).

Speed (D28): sending is optimistic: the user message appears immediately and reconciles with the server's ids when `createRun` returns; stream updates are throttled to animation frames.

## Owns

Run/stream code in `packages/server` and `packages/ai/src/runs/`, `packages/client` transport.

## Done when

Closing a client mid-stream and reconnecting resumes from the cursor (tested); a queued
second run starts when the first finishes; titles are generated by a job.

## Resolution (2026-09-27, loop)

Merged in [PR #16](https://github.com/connorwforsyth/openchat/pull/16): `packages/server` `createApp` (oRPC under `/api`, extra routers, session resolver, conversations/messages/runs, grant-aware access check, SSE stream route per decision 0004, `createServerFromEnv` degrading to 503 without a database); in-process run executor (queue per branch, approvals, cancel, usage), Postgres `StreamChannel` (batched appends + LISTEN/NOTIFY), pg-boss 12 job registry (titles, chunk pruning); `packages/client` (typed oRPC client, TanStack Query utils, resumable `useChat` transport, optimistic send).
