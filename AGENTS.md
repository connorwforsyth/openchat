# AGENTS.md

A self-hosted, multi-user AI chat platform with LibreChat's feature depth
(agents, MCP, files and RAG, branching, artifacts, sandboxes) on a clean
TypeScript stack. `PLAN.md` is the spec: read the decision (`D1`–`D26`) behind
whatever you touch before changing it. Work is tracked in `.wayfinder/`.

These rules are for every agent and human working here. The mechanical ones are
enforced in CI; the rest are enforced in review.

## Repo layout

bun workspaces + Turborepo. Packages use the `@workspace/*` scope.

```
apps/
  web/                Next.js 16 (App Router); mounts the API at /api
packages/
  ui/                 shadcn (Base UI) components + the theme (src/styles/globals.css)
  typescript-config/  shared tsconfig bases
scripts/ci/           repo guards run by `lint` (see "CI guards")
.wayfinder/           tracker: map, tickets, loop
```

Planned packages land per `PLAN.md` §6: `contract`, `shared`, `config`, `db`,
`auth`, `server`, `ai`, `mcp`, `sandbox`, `icons`, `i18n`, `composer`,
`chat-ui`, `code-ui`, `shortcuts`, `client`. `packages/*` are just-in-time
TypeScript: no build step, consumers compile them.

## Running things

```sh
bun install                 # also installs the lefthook pre-commit hook
docker compose up -d        # Postgres + pgvector on localhost:5432
docker compose --profile search up -d   # optional SearXNG
bun dev                     # turbo run dev
bun run check               # Ultracite (Biome) over the whole tree; `bun run fix` to fix
bun run check:guards        # repo guards; `bun scripts/ci/cli.ts tokens` for one
bun turbo typecheck lint test build     # what CI runs; must be green before merge
bun run test:e2e            # Playwright against a production build
```

- Turbo tasks: `dev`, `build`, `lint`, `typecheck`, `test`, `test:e2e`,
  `eval`, `db:generate`, `db:migrate`. Filter with `bun turbo test --filter=@workspace/ui`.
- **The app must boot with an empty `.env`.** Every variable is optional
  (`.env.example` documents them). A missing key degrades a feature; it never
  crashes boot. Agent features fall back to Ollama if it's running, and to
  nothing if it isn't.
- **Next 16 is not the Next you know.** Before writing anything in `apps/web`,
  read the relevant guide in `apps/web/node_modules/next/dist/docs/`, and heed
  deprecation notices. `apps/web/AGENTS.md` is generated by Next; leave it be.

## Engineering rules (`PLAN.md` D8)

- **Zod first.** Every data type is a zod schema; the TypeScript type is
  `z.infer<typeof Schema>`. Never hand-write a type that duplicates a schema.
  Parse at every boundary: HTTP, IPC, config, env, LLM tool input and output.
- **Functional core, imperative shell.** Domain logic is pure functions in
  packages (`buildBranchPath`, `resolveTools`, `effectiveGrants`, …). I/O lives
  at the edges.
- **Ports are function arguments.** A function that needs the database, a model
  or a clock takes it as a parameter typed by a small port interface
  (`RunExecutor`, `Storage`, `Decider`, …). No DI container, no service locator,
  no module-level singletons standing in for one.
- **No classes outside adapters.** An adapter wrapping a class-based SDK may be
  a class; everything else is functions and data.
- **Errors are values.** Return `Result<T, E>` from `@workspace/shared`
  (ticket 005); oRPC handlers use typed errors. Don't throw across layers; a
  throw is for bugs, and it's caught once at the shell.
- **Immutable data.** `readonly` types, no mutation of arguments, new objects
  over in-place edits.
- **Discriminated unions for states:** message parts, run status, sandbox
  status, job status. Switch exhaustively.
- **Formatting and lint:** Ultracite (Biome). Don't disable a rule to get green;
  if one is wrong for a line, use a `biome-ignore` comment that says why.
- Write like the surrounding code. Comments say why, not what.
- OSS dependencies only. Never add a paid service, create paid resources, or
  print a secret (not in logs, tests, fixtures or PR text).

## UI rules (`PLAN.md` D5, D12, D19)

- **Build from `@workspace/ui` components** (shadcn first, AI Elements only
  where shadcn has nothing). Add components with the shadcn CLI into
  `packages/ui`; they're owned source after that.
- **Semantic tokens only:** `bg-background`, `text-muted-foreground`,
  `border-border`, `ring-ring/50`, `--radius`. No hex, `rgb()`/`hsl()`/`oklch()`
  literals or palette classes (`bg-zinc-900`, `text-blue-500`) anywhere but
  `packages/ui/src/styles/globals.css`, which is the only place the theme lives.
  Need a new colour? Add a token there.
- **Icons only from `@workspace/icons`**, using lucide's names
  (`ChevronRightIcon`). Never import `lucide-react`, `@phosphor-icons/*`,
  `@tabler/icons-react`, `@hugeicons/*`, `@remixicon/*` or
  `@material-symbols/*` outside `packages/icons`. After `shadcn add`, run the
  icons codemod (ticket 006) to rewrite lucide imports.
- **Every user-facing string goes through Lingui macros** (`` t`…` ``,
  `<Trans>`, `plural`), including `aria-label`, `title`, `alt` and toasts. ICU
  plurals and select; never concatenate strings. `en` is the only locale for
  now, but nothing may be hard-coded.
- **Logical utilities** so RTL works later: `ms-/me-/ps-/pe-`, `start-/end-`,
  `text-start`, `border-s`. Not `ml-/mr-/pl-/pr-/left-/right-`.
- Keyboard-first and accessible: follow Vercel's Web Interface Guidelines for
  focus, labels and hit targets.

## Motion (`PLAN.md` D28)

- **Animate only `transform` and `opacity`** (colour transitions are fine).
  Never `height`, `width`, margins, `top`/`left` or `transition: all`.
- **Durations are tokens**, not numbers: `--motion-instant` (0 ms),
  `--motion-fast` (100 ms), `--motion-base` (250 ms) and `--motion-slow`
  (350 ms) in `packages/ui/src/styles/globals.css`. Write
  `duration-(--motion-fast)`; JavaScript timers read `motionMs` from
  `@workspace/ui/lib/motion`. Easing: `ease-motion-out` for enter and exit,
  `ease-motion-in-out` for things moving on screen.
- **Appear instantly, fade out over about 150 ms** (`--motion-exit`, or the
  `motion-exit` utility). Keyboard-driven UI (shortcuts, the palette, panel
  and sidebar toggles) doesn't animate at all.
- Respect `prefers-reduced-motion`: the tokens already shorten movement;
  keep fades.

## Contract changes (`PLAN.md` §3)

`packages/contract` (the oRPC + zod contract) and the port interfaces are the
frozen interfaces parallel work builds against.

- A change to `packages/contract` is its **own PR**, touching nothing else,
  that explains who needs it and what breaks. The owner reviews and merges it;
  agents never merge one.
- Until it merges, build against the current contract. If you're blocked,
  stop and report rather than editing the contract inside a feature PR.
- The same goes for port interfaces in `packages/*/src/ports/`.

## Testing (`PLAN.md` D9)

- **Vitest** everywhere (not Jest, not `bun test`). Each package with tests has
  a `vitest.config.ts` (`defineProject`) and is listed by the root
  `vitest.config.ts`. Tests sit next to the code as `*.test.ts(x)`.
- **Never hit a real provider or the network.** LLM tests use
  `MockLanguageModelV4` from `ai/test` plus recorded fixtures; the Decider uses
  `Experimental_EvaluationMockModelV4`. Outbound HTTP is mocked with **MSW**.
- **DB tests** use **PGlite** (in-process Postgres + pgvector). CI's Docker
  Postgres is for integration tests only.
- **API tests** call oRPC handlers in-process through Hono `app.request()`.
- **Components:** Vitest browser mode + Testing Library. **E2E:** Playwright.
  A browser-mode package's `test` script is
  `bun ../../scripts/ci/browser-lock.ts vitest run`, so one browser run is up
  per machine at a time, and its config sets `connectTimeout`, `maxWorkers`
  and the in-process network service (ticket 043; enforced by
  `scripts/ci/vitest-timeouts.test.ts`). Copy an existing browser package.
- Test the pure core directly; fake ports with the in-memory fakes that ship
  next to each port. No `.only` or `.skip` in commits.

## Brand (`PLAN.md` D18)

The product's name is a working codename and will change. It may appear only
in: the `brand:` block of `app.config.yaml` / `app.config.example.yaml`, the
root `package.json` `name`, Docker image and container names, `PLAN.md`,
`.wayfinder/`, `.github/` and `bun.lock`. Everywhere else, read the name from
config at runtime. Packages use `@workspace/*`, never the brand.

## CI guards (`scripts/ci/`)

Run as part of `lint` (and as their own CI step). Each prints
`path:line:col  message` and exits non-zero on a violation.

| Guard | Fails on |
|---|---|
| `tokens` | hex, colour functions, palette classes or `--color-<palette>` in `apps/` and `packages/` |
| `icon-imports` | an icon library imported outside `packages/icons` |
| `brand` | the codename outside the places listed above |
| `lingui` | catalogs out of date after `lingui extract --clean`, or missing translations |

- A genuine `tokens` false positive (say, an anchor `#feed`) takes
  `ci-guard-ignore tokens: <why>` in a comment on that line or the line above.
  Use it rarely; a reviewer will ask.
- `scripts/ci/icon-imports.allow` lists files still pending the icons codemod.
  It only shrinks: a listed file that no longer offends fails the guard.
- Guards are pure functions with tests against fixtures in
  `scripts/ci/__fixtures__/` (which the guards and Biome skip). Add a fixture
  when you change a rule.

## Git and PRs

- One ticket, one branch, one PR, in its own worktree. Edit only the paths your
  ticket **Owns** (`.wayfinder/map.md` has the register); if you must touch
  anything else, stop and say why.
- Never push to `main` or force-push. Never commit `node_modules`, `.next`,
  `.turbo`, `.env*` or build output.
- The pre-commit hook runs `ultracite check` on staged files. Fix what it finds;
  don't skip it.
