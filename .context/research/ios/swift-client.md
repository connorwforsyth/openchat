# The Swift client stack against our server (ticket 306)

Research for the iOS map (300). Nothing in the repo was changed; every experiment ran in
`/tmp/ios184`. openchat paths are relative to the repo root at `51c75b2`.

**Answer in one paragraph.** `swift-openapi-generator` 1.9.0 reads `openapi.json` without
errors and the output compiles (95k lines of types, 24k of client, about 4.5 min for a cold
debug build in a 4-core Linux container: 2.5 to 4.5 minutes, the generated module included). As emitted today, though, it **silently drops all
120 nullable fields** (the generator prints 135 warnings, one per use of a shared schema) and turns every discriminated union into a struct of untyped
`OpenAPIValueContainer`s. A ~150-line preprocessing script, run before generation, fixes
both: every contract fixture then decodes. The run stream needs no generator help: the
runtime's own SSE decoder handles our `id:`/`data:`/`[DONE]` format. `bearer()` is enabled,
so email sign-in is one `POST` that hands back a token in a header. Social and OIDC sign-in
need one small server addition, a native hand-off route plus Better Auth's
`oneTimeToken()` plugin, because a custom-scheme callback is refused today and putting the
long-lived token in a redirect URL is the thing to avoid. **No stream or view tickets are
needed for v1**: URLSession sends `Authorization` on SSE and image requests, and the
artifact runtime gets its content by `postMessage`, not by an authenticated URL.

Why, from the generator's source and tracker:

- **`null` is unsupported as a schema** (`Sources/_OpenAPIGeneratorCore/Translator/TypeAssignment/isSchemaSupported.swift:176`:
  `case .not, .null: return .unsupported`). An `anyOf` is supported only if all its
  children are (`:161-163`), and an unsupported property is skipped. The documented 3.1
  route is a type array (Supported-OpenAPI-features.md:172: "add `null` in `types`
  instead"), which works: a probe property `type: [string, null]` became `String?`.
  `anyOf [$ref, null]` and `oneOf [$ref, null]` are dropped just the same.
- **`const` is not supported** (open issue
  [apple/swift-openapi-generator#261](https://github.com/apple/swift-openapi-generator/issues/261),
  last activity 2024-10; the maintainers' advice in #891 is a one-element `enum`). An
  untyped `{const: "text"}` becomes `OpenAPIValueContainer`; with `type: string` it becomes a
  one-case enum. So `MessagePart` today is a struct with ten optional `valueN` members,
  each of which decodes any part, since nothing pins its `type`.
- **`discriminator` is supported** only when every `oneOf` child is a `$ref`
  (Supported-OpenAPI-features.md:160-162). Given that, the output is good: `MessagePart`
  becomes `enum MessagePart { case text(MessagePartText), case toolCall(…), … }`, switching
  on `type`.
- Constraints (`pattern`, `minLength`, `maximum`, `exclusiveMinimum`, `default`…) are
  ignored (Supported-OpenAPI-features.md:138-170); fine, the server validates.
- `format: uuid` stays `String`. `format: date-time` becomes `Date`.
- **Large spec:** not a problem for generation (about 5 s). Compile time is the cost. Use
  `filter` (by tag or operation id) to generate only what the app calls, if build times
  hurt (Configuring-the-generator.md:39-43).

## 3. What needs fixing, and where

**Recommendation: a preprocessing step in `apps/ios`, not a contract change and not an
OpenAPI Overlay.** The rewrites are structural (hoisting inline union members into
components), which Overlay 1.0's JSONPath `update`/`remove` actions can't express
generically. The contract's JSON is correct 3.1; the gap is the generator's. A script
(~150 lines; the prototype is `/tmp/ios184/scripts/prepare.py`, worth porting to TypeScript
under `apps/ios/scripts/` so it runs with bun) reads `packages/contract/openapi.json` and
writes `apps/ios/…/openapi.json` for the generator's build plugin. A unit test pins its
output against the committed spec, so a contract change that adds a new shape fails loudly.

| Problem | Fix in the preprocessor | Verified |
|---|---|---|
| `const: v` ignored | `type: <json type of v>, enum: [v]` (161 sites) | yes |
| `anyOf [scalar, null]` dropped | merge into `type: [<type>, "null"]` (most of the 120 nullable unions) | yes: `latestVersionId: String?` |
| `anyOf [$ref or union, null]` dropped | drop the `null` branch and remove the property from the parent's `required`; `decodeIfPresent` reads JSON `null` as `nil` | yes: `Conversation` with `defaultTarget: null` decodes |
| Discriminated unions are structs of optional `valueN` | find `anyOf` whose object members all require one property with a single string `const`; hoist inline members into `components/schemas/<Parent>_<Value>`, emit `oneOf` + `discriminator { propertyName, mapping }` (67 unions, 121 hoisted schemas) | yes: `MessagePart`, `RunState`, `ApprovalDecision` become Swift enums |
| Branded-id unions (`anyOf` of `uuid` strings differing only in `description`, 9 sites such as `meta.models?contextId`) become wrapper structs | collapse to one `string` | yes: `contextId: String?` |

Things the preprocessor **can't** fix, so they belong to the Swift layer or a later
contract PR:

1. **Explicit `null` in request bodies.** Generated `Codable` encodes `nil` by omitting the
   key (probe: `JsonPayload(ifMatch: nil)` encodes as `{"content":"x","path":"a.txt"}`).
   Where the contract gives `null` a meaning distinct from "absent", Swift can't say it:
   `sandbox.writeFile` `ifMatch: null` (create-only), `conversations.update`
   `defaultTarget`, `me.updateSettings` `defaultTarget`/`locale`, `teams.create/update`
   `parentId`, `orgs.update` `logoUrl`, `library.create/update` `icon`, `memory.update`
   `baseVersionId`, `conversations.updateMyState` `activeLeafId`/`followingUserId`,
   `runs.create` `input.parentId`. For v1, the iOS app needs none of these except perhaps
   "clear the default model". **Fix where it's needed:** a hand-written body for that one
   call via `typeOverrides` (Configuring-the-generator.md:48-49). A contract change only if
   several pile up.
2. **Top-level `X | null` responses** (`sandbox.get`, `artifacts.publication`,
   `feedback.get`): the body type isn't optional, so a `null` body won't decode. Hand-write
   those three calls or avoid them in v1; a later contract PR could wrap them
   (`{ sandbox: Sandbox | null }`).
3. **Forward compatibility.** A newer server that adds a `MessagePart` type, a run status
   or an artifact `kind` breaks decoding of the whole message or list on an older app
   (probe: `{"type":"chart"}` throws `unknownOneOfDiscriminator`; string enums are
   `@frozen`). The web client is redeployed with the server; the App Store binary isn't.
   Two halves: the preprocessor adds an `unknown` fallback (generate the union, then
   decode via a thin hand-written wrapper that catches `unknownOneOfDiscriminator` into
   `.unsupported(type:)`), and the contract README rule from ticket 155 says new union
   members or enum values are capability-gated or bump `apiVersion`. **Worth stating in
   155's README rule.**
4. **Dates.** The server writes `toISOString()` (always milliseconds: fixtures use
   `new Date(…).toISOString()`, `packages/contract/src/fixtures.ts:34-35`). The runtime's
   default `.iso8601` transcoder **fails** on those (probe:
   `Expected date string to be ISO8601-formatted`).
   `.iso8601WithFractionalSeconds` (`swift-openapi-runtime …/Conversion/Configuration.swift:72-74`)
   works but rejects strings without fractions, which `offset: true` permits. Ship a
   ~10-line `DateTranscoder` that tries both, set in `Configuration(dateTranscoder:)`.
5. **Names.** `idiomatic` naming turns `me.get` into `me_get(…)` and `Operations.Me_get`.
   It's harmless; `nameOverrides` can tidy the handful the app calls most.

## 4. The run stream (`GET /api/runs/{id}/stream`)

Wire format (`packages/server/src/stream/sse.ts`, contract README "The run stream",
`packages/contract/README.md:112-131`):

- Headers: `content-type: text/event-stream; charset=utf-8`,
  `x-vercel-ai-ui-message-stream: v1`, `cache-control: no-cache, no-transform`,
  `x-accel-buffering: no` (`sse.ts:11-17`).
- Each chunk: `id: <seq>\ndata: <UIMessageChunk JSON>\n\n` (`sse.ts:84-89`). `seq` starts
  at 1. The end: `data: [DONE]\n\n` with no `id` (`sse.ts:92-93`). Every 15 s:
  `: keep-alive\n\n` (`sse.ts:20`, `:98-104`).
- Resume: `?cursor=<last seq>` wins over `Last-Event-ID`; anything unparseable replays
  from 0 (`sse.ts:30-42`). A finished run replays and closes.
- Errors before streaming are JSON: 401 `UNAUTHORIZED`, 404 `NOT_FOUND` (also for no
  access), 503 when the channel is down (`app.ts:113-131`, `sse.ts:57-66`).
- Text and reasoning deltas are coalesced before storage, so one `text-delta` may carry
  many tokens (`packages/server/src/stream/coalesce-deltas.ts:1-14`).
- Payloads are AI SDK `UIMessageChunk`s (`ai@7.0.116`, `dist/index.d.ts:2477`): `start`,
  `start-step`, `text-start|delta|end`, `reasoning-start|delta|end`, `reasoning-file`,
  `tool-input-start|delta|available|error`, `tool-approval-request|response`,
  `tool-output-available|error|denied`, `source-url`, `source-document`, `file`,
  `data-<name>` (ours: `data-artifact-ref`, `data-annotation-ref`,
  `packages/ai/src/messages/to-ui.ts:208-218`), `message-metadata`, `finish-step`,
  `reset-step`, `finish`, `abort`, `error`, `custom`. The contract keeps them opaque
  (`jsonValueSchema`), so **the Swift chunk enum is hand-written**, decoding `type` with
  an `unknown` fallback.
- The web client's reader is the reference: `packages/client/src/run-stream.ts`
  (`splitSse` `:33-54`, cursor dedupe `:178-185`, retry on 5xx/429 and drops, give up on
  other 4xx `:123`, backoff 250 ms doubling to 5 s `:58-59`).

The generated `runs_stream` returns the body as `HTTPBody` (an
`AsyncSequence<ArraySlice<UInt8>>`), and `swift-openapi-runtime` already ships a
spec-conforming SSE decoder: `asDecodedServerSentEvents(while:)`, which skips `:` comments,
keeps `id`, and stops when the predicate sees the terminator
(`Sources/OpenAPIRuntime/EventStreams/ServerSentEventsDecoding.swift:104-107`, `:200-201`;
"Useful OpenAPI patterns" doc in the generator, lines 106-121). Use
`URLSessionTransport` (`swift-openapi-urlsession` 1.3.2), which streams response bodies on
iOS rather than buffering (`URLSessionTransport.swift:90-144`).

Sketch (Swift 6, iOS 26; not compiled). The generated names are real:
`runs_stream`, `query.cursor`, `headers.lastEventID`, `ok.body.textEventStream`.

```swift
import OpenAPIRuntime

enum RunStreamEvent: Sendable {
    case chunk(seq: Int, UIChunk)   // hand-written enum over `type`, with .unknown
    case done
}

/// One run's chunks, resuming from `cursor` across drops. Finishes at [DONE];
/// throws on a non-retryable 4xx or after `maxRetries` failed reconnects in a row.
func runStream(
    client: Client, runId: String, from cursor: Int = 0, maxRetries: Int = 5
) -> AsyncThrowingStream<RunStreamEvent, any Error> {
    AsyncThrowingStream { continuation in
        let task = Task {
            var cursor = cursor
            var failures = 0
            while !Task.isCancelled {
                do {
                    let output = try await client.runs_stream(
                        path: .init(id: runId), query: .init(cursor: cursor))
                    let body = try output.ok.body.textEventStream   // non-200 → throws
                    let events = body.asDecodedServerSentEvents(
                        while: { $0 != ArraySlice("[DONE]".utf8) })
                    for try await event in events {
                        guard let data = event.data,
                              let seq = event.id.flatMap(Int.init), seq > cursor
                        else { continue }   // replayed or id-less: already seen
                        let chunk = try JSONDecoder().decode(UIChunk.self, from: Data(data.utf8))
                        cursor = seq
                        failures = 0
                        continuation.yield(.chunk(seq: seq, chunk))
                    }
                    // The `while` predicate ends the sequence at [DONE]; a dropped
                    // connection also just ends it. Tell them apart:
                    if await runIsFinished(client, runId) {     // or track a sawDone flag
                        continuation.yield(.done); continuation.finish(); return
                    }
                } catch let error as RunStreamFatal {          // 401/403/404 from `output`
                    continuation.finish(throwing: error); return
                } catch {
                    failures += 1
                    if failures > maxRetries { continuation.finish(throwing: error); return }
                }
                try? await Task.sleep(for: .milliseconds(min(250 << (failures - 1), 5_000)))
            }
        }
        continuation.onTermination = { _ in task.cancel() }
    }
}
```

Notes on the sketch:

- The `while:` predicate is the clean way to see `[DONE]`, but the sequence ending looks
  the same whether `[DONE]` arrived or the socket dropped. In the real code, run the
  predicate as `{ bytes in if bytes == done { sawDone.set() }; return bytes != done }`
  with a small `Mutex<Bool>`, rather than asking the server.
- Persist `cursor` per run (SwiftData), so a cold launch or `scenePhase == .active` resumes
  where it left off: that's the "resume from cursor on foreground" item in the map.
- Approvals arrive as `tool-approval-request` chunks; answering is the generated
  `runs_submitApprovals`. The stream stays open (heartbeats) while it waits.
- If `runtime` ever disagrees with our format, the fallback is ~40 lines over
  `URLSession.bytes(for:)` and `.lines`, a port of `splitSse`. But the runtime decoder is
  spec-conforming and tested, so prefer it.

## 5. Sign-in

### What the server has

- Better Auth `1.7.6` with `emailAndPassword`, `organization`, `admin`, **`bearer()`**,
  `genericOAuth` (OIDC from `app.config.yaml`), and GitHub/Google `socialProviders` when
  their credentials exist (`packages/auth/src/server.ts:284-297`). Mounted at
  `/api/auth/*` (`packages/server/src/server.ts:574`).
- Every API route resolves the session with `auth.api.getSession({ headers })`
  (`server.ts:181-197`), so `Authorization: Bearer <token>` works on every oRPC route and
  on the run stream, because `bearer()`'s before-hook rewrites it into the session cookie
  (`better-auth/dist/plugins/bearer/index.mjs:23-49`).
- `bearer()`'s after-hook copies any new session cookie into a **`set-auth-token`**
  response header (`bearer/index.mjs:50-67`). The token is the signed cookie value
  (`<token>.<hmac>`); send it back verbatim.
- `trustedOrigins` is `BETTER_AUTH_URL`, its loopback aliases, and `TRUSTED_ORIGINS`.
  `originSchema` accepts **only http(s) origins** (`packages/auth/src/origins.ts:30-52`), so
  a custom-scheme `callbackURL` such as `myapp://auth` is refused today with
  `INVALID_CALLBACK_URL` (`better-auth/dist/api/middlewares/origin-check.mjs:47-69`).
- No `expo()` and no `oneTimeToken()` plugin.
- `/api/config` lists providers as `{ id, name }` (`packages/contract/src/schemas/meta.ts:87-91`).

### Email and password: native, no browser

1. `POST {instance}/api/auth/sign-in/email` with JSON `{ email, password }`. Send **no
   `Origin` and no cookies**: Better Auth checks origin only when the request carries
   cookies or an `Origin`/`Referer`/`Sec-Fetch-*` header
   (`origin-check.mjs:96-118`, `:131-152`), so a plain URLSession request passes.
   **Use a `URLSessionConfiguration.ephemeral` session, or set
   `httpShouldSetCookies = false`.** Otherwise the default cookie store saves the
   `set-cookie` and later requests carry a cookie, which turns on the origin check and
   fails with `MISSING_OR_NULL_ORIGIN`.
2. Read `set-auth-token` from the response; save it in the Keychain (below).
3. Every request after that, the generated client's middleware adds
   `Authorization: Bearer <token>`. Sign-up is the same against `/sign-up/email`
   (subject to `decideSignUp`, `server.ts:302-327`).
4. Sign out: `POST /api/auth/sign-out` with the bearer, then delete the Keychain item and
   the SwiftData cache.

Do this as a native form. A browser sheet just for a password is worse UX and adds nothing.

### Social and OIDC: `ASWebAuthenticationSession` and a one-time hand-off

The `expo()` plugin's pattern (`@better-auth/expo@1.7.6`, `dist/index.js`) is:

- the app asks `/sign-in/social` for the provider URL;
- the browser opens `/expo-authorization-proxy?authorizationURL=…`, which plants the signed
  `state` cookie in the browser's jar (`:7-35`);
- after the provider callback, an after-hook appends the **whole `set-cookie` header** as
  `?cookie=` to the custom-scheme redirect (`:62-83`).

It works, but it puts the long-lived session token in a URL, which iOS hands to the app
and which anything logging URLs can see. It also needs the `expo-origin` header dance and
custom schemes in `trustedOrigins`. It's built for `expo-web-browser`; nothing in it is
Expo-specific, so it isn't required for Swift.

**Recommended flow** (needs a server change; see "Tickets" below):

1. Native: the user picks a provider from `/api/config` `auth.providers`. The app opens
   `ASWebAuthenticationSession(url: {instance}/auth/native?provider=<id>&state=<random>,
   callback: .customScheme("<scheme>"))`, with `prefersEphemeralWebBrowserSession = true`
   so the instance's browser cookies don't leak into, or out of, the system browser.
   `Callback.customScheme` is iOS 17.4+ (Apple docs, `ASWebAuthenticationSession.Callback`).
   The `https(host:path:)` callback **can't** be used: its host "must be a member of a
   domain associated with the app", and a self-hosted instance's domain isn't known when
   the app is signed.
2. Server, `/auth/native` (a small page or route in the web app): if not signed in, it
   runs the normal web sign-in for that provider (`/sign-in/social` or
   `/sign-in/oauth2`) with `callbackURL` set to itself. That's a same-origin URL, so it's
   already trusted and needs no `trustedOrigins` change. Email, GitHub, Google and every
   OIDC provider follow their normal web paths, including `decideSignUp` refusals, which
   the page can show.
3. Once signed in (session cookie in the ephemeral browser jar), `/auth/native` calls
   `auth.api.generateOneTimeToken` (the `oneTimeToken()` plugin: 32 random characters,
   stored in `verification`, single use, 3-minute default expiry;
   `better-auth/dist/plugins/one-time-token/index.mjs:20-60`). It then redirects to
   `<scheme>://auth?token=<ott>&state=<state>`. The scheme comes from the brand config,
   not a literal (D18). It must be on a fixed allowlist, never taken from the query.
4. Native: check `state`, then `POST /api/auth/one-time-token/verify { token }` (no
   cookies, ephemeral session). The plugin consumes the token, sets the session cookie
   (`:74-87`), and `bearer()` turns that into `set-auth-token`. Save it to the Keychain.
5. Done: the same bearer path as email. The only thing that ever rode in a URL is a
   3-minute, single-use token.

Alternatives considered:

- Add `expo()` and a custom scheme to `trustedOrigins` (puts the session token in a URL;
  needs `originSchema` widened).
- The `https` callback (impossible for self-hosted).
- Running OAuth natively with PKCE against GitHub/Google directly (every instance would
  need its own iOS client registered with each provider, and OIDC providers vary).

### Keychain

- One generic-password item per instance: `kSecClassGenericPassword`, service
  `<bundle id>.session`, account = the instance origin (later `instanceId` once `/api/config`
  has one; see `remote-mobile.md` §3.6).
- `kSecAttrAccessibleAfterFirstUnlockThisDeviceOnly`, so background refresh and push
  handling can read it after a reboot-then-unlock, and it never syncs or migrates to
  another device.
- No `kSecAttrSynchronizable`. Wipe on sign-out and on "remove instance".
- Sessions follow Better Auth's expiry (7 days by default, refreshed on use). A 401 means
  "show sign-in", not "retry".
- The device appears in Better Auth's `listSessions`, which the planned "Devices" settings
  page (`remote-mobile.md` §3.5) can label and revoke.

## 6. Do SSE, images and artifacts need short-lived tickets?

`remote-mobile.md` §3.5 recommends tickets because `EventSource`, `<img>` and iframes
can't send headers. For a native Swift app:

| Resource | How iOS loads it | Ticket needed? |
|---|---|---|
| Run stream | URLSession with an `Authorization` header (generated `runs_stream`) | **No** |
| API JSON | same | No |
| Uploaded files and images | `files.getUrl` already returns "a short-lived signed download URL" (`packages/contract/src/routes/files.ts:53-56`), which needs no auth to fetch | No (it already is one) |
| Link-preview images (`/api/link-preview/image?src=…`) | `authed` (`packages/contract/src/routes/link-preview.ts:40`). `AsyncImage` can't add headers, so use a small image loader over the same authed `URLSession` | No, but don't use bare `AsyncImage` |
| Artifacts | The runtime on the artifacts origin is sent its content by `postMessage` from the embedding page (`apps/artifacts/src/main.ts:15-26`); it fetches nothing with the user's credentials | No |
| Published sites | public `/s/<token>/…` | No |

**Conclusion: no stream or view ticket for v1.** Revisit if a WKWebView ever has to
load an authenticated app URL (for example a future "open this chat on the web" view).

For the artifact `WKWebView`:

- The runtime insists on `?parent=<app origin>` and posts to `window.parent`
  (`apps/artifacts/src/main.ts:22-26`).
- Its CSP is `frame-ancestors <ARTIFACTS_APP_ORIGINS>` (`apps/artifacts/src/headers.ts:50`).

So load a tiny host page with `loadHTMLString(_:baseURL: instanceOrigin)`. It iframes
`{artifactsOrigin}/?parent={instanceOrigin}`, forwards the `RenderRequest` it gets from
native (`WKScriptMessageHandler` / `evaluateJavaScript`), and relays `rendered`/`error`/
height back. Whether WebKit's `frame-ancestors` check accepts an origin that comes from
`baseURL` is **unverified**; check it in the prototype ticket (309). If it doesn't, the
fallback is a static `/artifacts-host` page on the app origin.

## 7. `/api/config` (ticket 155) and what iOS needs from it

`publicConfigSchema` today (`packages/contract/src/schemas/meta.ts:78-109`) has:

- `brand { name, logoUrl, faviconUrl }`, `auth { providers, signup }`;
- `features`, `limits`, `policies`, `sandbox`, `artifacts.siteOrigins`.

Ticket 155 adds `apiVersion` and `capabilities`. For iOS, the same contract PR (or a sibling
one) should also consider:

- **`instanceId`**: a stable id to key Keychain items, SwiftData stores and push
  registration (`remote-mobile.md` §3.6). An origin works until an instance moves.
- **Brand accent and font**: the iOS map says these come from instance config at runtime,
  but `brand` has neither today.
- **The native sign-in capability** (`auth.native`), so a new app on an old server can say
  "this server is too old for app sign-in" instead of failing in the browser sheet.
- The rule in §3.3: new union members and enum values are capability-gated or bump
  `apiVersion`, because frozen Swift enums reject unknown values.
